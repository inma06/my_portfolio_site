# 밀크코퍼레이션 유아동복 앱 개발 상세 회고 — 2021.07 ~ 2022.04

## 1. 프로젝트 개요
유아동복 쇼핑몰의 모바일 앱 프론트엔드 전반을 단독 담당했습니다. **초기 셋업부터 1.3.0 정식 출시까지 약 10개월** 동안 Flutter 로 iOS · Android 동시 개발·운영을 진행했고, 단순 화면 구현뿐 아니라 상태관리 아키텍처 결정, 외부 SDK 통합, 스토어 심사 대응, 운영 게이트(강제 업데이트) 같은 출시·운영 이슈를 함께 다뤘습니다.

## 2. 상태관리 — GetX

### 2.1 선택 이유
초기 단독 개발 환경에서 라우팅 / 상태 / 의존성 주입을 한 패키지로 가볍게 다룰 수 있는 GetX 를 채택했습니다. Provider/Bloc 대비 부트스트랩 비용이 낮아 출시 속도를 우선해야 하는 단계에 적합했습니다.

### 2.2 중복 라우팅 처리
사용자가 같은 버튼을 빠르게 두 번 누르거나, 푸시 / 딥링크로 진입할 때 같은 화면이 스택에 여러 번 쌓이는 문제가 있었습니다. 다음과 같은 규칙으로 일관되게 차단해 백 버튼 동작이 뒤틀리지 않도록 정리했습니다.

- 라우팅 가드: 진입 직전 권한 / 상태 체크
- 중복 push 차단: "현재 라우트와 같으면 push 무시"
- 모달 / 바텀시트도 동일 인스턴스 중복 표시 방지

## 3. Firebase 통합

- **Auth** — 로그인 / 가입 흐름
- **FCM** — 푸시 알림 (주문 상태, 마케팅)
- **Crashlytics** — 운영 중 크래시 추적과 핫픽스 사이클 안정화

## 4. 결제 — 아임포트

- 결제 요청 → 결과 콜백 → 서버 검증 → 주문 확정 흐름을 한 묶음으로 처리
- 결제 콜백 누락 / 사용자 이탈 / 네트워크 단절 케이스가 발생해도 결제 정합성이 깨지지 않도록 서버 검증과 함께 묶음

## 5. 애널리틱스 — 에어브릿지 (Airbridge, AB108)

- 신규 설치 / 회원가입 / 결제 / 핵심 화면 진입 등의 전환 이벤트를 어트리뷰션 SDK 로 송신
- 광고 채널별 ROI 추적 가능
- 디바이스·이벤트 매칭 로직은 SDK 가이드에 따라 정착시키고, 운영팀에 발화 시점을 명세로 전달

## 6. 권장 / 강제 업데이트 게이트

앱 부팅 시 서버에서 **최소 지원 버전 · 권장 버전** 을 받아오고, 다음과 같이 분기했습니다.

- **권장 업데이트** — 모달로 안내, 사용자가 스킵 가능
- **강제 업데이트** — 모달이 dismiss 되지 않고 스토어 이동 버튼만 노출

크리티컬 결제·인증 이슈가 있는 구버전에 사용자가 묶이지 않도록 **운영팀이 서버 설정만으로 즉시 강제 업데이트를 켤 수 있게** 만든 것이 핵심입니다. 앱 배포 사이클을 기다리지 않고 운영팀이 게이트를 통제할 수 있게 되었습니다.

## 7. 스토어 심사 반려 대응

- 출시 / 업데이트 과정에서 받은 반려 사유를 유형별로 분류 (UGC 정책, 결제 안내 문구, 권한 사용 사유, 메타데이터 등)
- 유형별 재제출 체크리스트를 정리해 다음 심사부터는 같은 사유로 반복 반려되지 않도록 정착
- 이 노하우가 이후 라임프렌즈 / 사주사이트 / AI 캐릭터 채팅 서비스의 심사 대응의 출발점

## 8. 출시 범위
- 초기 셋업 → 1.0 정식 출시 → 1.3.0 까지 운영 업데이트 사이클을 거치며 유아동복 카테고리의 시즌성·이벤트 페이지·결제·푸시 운영 흐름을 안정화
