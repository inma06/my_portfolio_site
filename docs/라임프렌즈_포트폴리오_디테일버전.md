# 라임프렌즈 (Just Thank You) 개발 상세 회고 — 2022.05 ~ 2023.01

## 1. 프로젝트 개요
"일상의 감사를 카드와 짧은 글로 표현하는 감성 SNS" 라는 컨셉의 Flutter 앱입니다. iOS · Android 동시 빌드·배포로 운영했고, SNS 도메인(타임라인 · 알림 · 팔로우 · 작성/조회)에 더해 **카드 선물하기 결제 흐름**까지 다루는 복합 도메인 앱이었습니다.

## 2. CI/CD — Flavor + Fastlane 으로 사이클 단축

### 2.1 Flutter Flavor 분리
dev / staging / prod 빌드 타깃을 분리해 환경별로 다른 firebase 설정, API 엔드포인트, 앱 아이콘·이름을 적용했습니다. 동일 기기에 dev / prod 앱을 동시에 설치해 비교 검증할 수 있게 되어 QA 효율이 올라갔습니다.

### 2.2 Fastlane 으로 스토어 업로드 자동화
- iOS: 코드 사이닝(match), 빌드 번호 자동 증가, TestFlight 업로드
- Android: 빌드, 서명, Play Console 내부 트랙 업로드
- 한 명령으로 환경별 빌드·배포가 끝나도록 정리

### 2.3 결과
매 QA 전달마다 손으로 챙기던 단계가 사라지면서, **디자인/기획 피드백을 받은 당일 안에 검증 빌드를 올리는 사이클**이 가능해졌고, 출시 직전 핫픽스 대응 속도가 크게 개선되었습니다.

## 3. 상태관리·아키텍처

### 3.1 BLoC 패턴
화면 로직을 Bloc 단위로 분리해 UI 코드가 단순한 "state → widget" 매핑에 집중하도록 정리했습니다. 비즈니스 분기/사이드 이펙트는 Bloc 안으로 모았습니다.

### 3.2 Layered Architecture + DDD 스타일
- **Domain** — 엔티티 / Value Object / UseCase / Repository 인터페이스
- **Application** — Bloc, 어플리케이션 서비스
- **Infrastructure** — Repository 구현, Firebase / REST API 클라이언트, 매퍼
- **Presentation** — Widget

도메인 레이어가 외부 의존성(Firebase, REST 응답 포맷 등)에 묶이지 않도록 인터페이스 기반 의존성 역전을 유지했습니다.

### 3.3 얻은 효과
신규 기능 추가 시 영향 범위가 도메인/UI 안쪽으로 국한되었고, 백엔드가 Firestore → REST API 로 바뀌는 큰 변경에서도 Infrastructure 계층만 교체해 비교적 매끄럽게 마이그레이션할 수 있었습니다.

## 4. 백엔드 마이그레이션 대응 — Firestore → AWS Lambda + PostgreSQL

기존 백엔드는 Firebase Firestore 기반이라 클라이언트가 SDK 를 통해 직접 쿼리·실시간 구독을 사용하는 구조였습니다. 운영 비용·관계형 데이터 요구·복잡한 조인이 늘어나면서 백엔드가 **AWS Lambda(서버리스 함수) + RDB (PostgreSQL)** 기반으로 전환되었고, 클라이언트도 다음을 함께 재정비했습니다.

- **데이터 모델 재정의** — Firestore 의 nested document 구조에 맞춰져 있던 모델을 관계형 응답 스펙에 맞게 재설계.
- **실시간 갱신 흐름 교체** — Firestore snapshot listener 에 의존하던 부분을 REST 폴링 / 명시적 refresh / Pull-to-refresh 모델로 대체. 알림성 흐름은 별도 푸시 / 이벤트 채널로 분리.
- **추상화 레이어 덕분에 가능했던 점진 교체** — Repository 인터페이스 뒤로 데이터 소스를 감춰두었기 때문에, 화면 단의 코드는 거의 그대로 두고 Infrastructure 구현만 교체하면서 단계적으로 이관할 수 있었습니다.

## 5. 스토어 심사 — Google UGC 정책 반려 대응

- **반려 사유** — 사용자 생성 콘텐츠(UGC) 가 있는 앱이 갖춰야 할 신고 · 차단 · 사후 모더레이션 정책 보강 요구.
- **대응**
  - 게시물 신고 / 사용자 차단 흐름 정비
  - 운영자가 처리 가능한 모더레이션 파이프 연결
  - 정책 문구를 앱 내부와 스토어 페이지에 일관성 있게 반영
- **결과** — 재심사 통과, 이후 다른 프로젝트의 심사 대응 노하우의 출발점.

## 6. 선물하기 결제

- **아임포트 SDK 연동** — "감사 카드" 를 친구에게 선물하는 결제 흐름 구현
- 결제 요청 → 결과 콜백 → 서버 검증 → 카드 발송까지를 한 흐름으로 묶고, 결제 실패 / 사용자 이탈 / 네트워크 단절 케이스를 분리 처리
